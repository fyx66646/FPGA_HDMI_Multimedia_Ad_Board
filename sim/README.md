# spectrum_core ModelSim 仿真

## 内容

| 文件 | 说明 |
|------|------|
| tb_spectrum_core.v | 仿真激励与自检(1875Hz 正弦, 每样本连发两拍, 模拟真实 48kHz 样本重复链路) |
| spectrum_core_sim.v | spectrum_core 的仿真副本(与原文件唯一差异: `wire bin` 声明提前到使用处之前, 逻辑等价) |
| sim_batch.do | 批处理仿真脚本: `vsim -c -do sim_batch.do` |
| sim_gui.do | 图形界面仿真脚本(含波形窗口): `vsim -do sim_gui.do` |

## 运行

```bash
cd sim
G:/modelsim/win64/vsim.exe -c -do sim_batch.do     # 批处理
G:/modelsim/win64/vsim.exe -do sim_gui.do          # 图形界面
```

## 激励设计

- 时钟 25MHz(video_clk), 与板级一致;
- 1875Hz 正弦 = 64 点 FFT 的第 5 频点(375Hz x 5), 幅度 0.4 满幅;
- 音频链路"每样本连发两帧", 因此每个样本连续两拍 `sample_valid=1`, 模块取每对第一个(有效采样率 24kHz);
- 自检打印 32 频点电平并给出 PASS/FAIL。

## 已知发现(2026-10-31 仿真定位, 已修复)

1. **频谱输出与理论 DFT 有偏差**：对单音 1875Hz 输入, 能量未集中在第 5 频点, 而是弥散到全频段。用 Python 精确复现 RTL 的蝶形算法 + numpy 参考 DFT 对比, 定位根因为**蝶形引擎要求输入按位反序排列, 而采样写入是自然序直写**——修复: 采样写地址做 6 位位反序(`mem[bitrev(waddr)]`)。
2. **FFT 启动流水未预热**：进入 FFT_RUN 的头两拍, 读地址流水线里仍是空闲期的陈旧地址, 导致第 (0,1) 号蝶形被连续处理三次(单位冲激测试呈"偶数频点有值、奇数频点为零"的特征图案)。修复: 预热期(fcnt<2)跳过写回。
3. **修复验证**：上述两处修复后, ModelSim 仿真 PASS——1875Hz 单音能量集中在 bin 5(电平 34), 其余频点全为 0, 与理论一致; 修复已同步到工程源码并重新编译(bit 见 best_result)。上板后请验证频谱条, 并按惯例做手动切图回归。


## 仿真波形对照分析(2026-11-01, 本人微信导出的波形截图)

收到两张本人导出的 ModelSim 波形截图(顶层 tb_spectrum_core), 与本 testbench 逐信号比对结论如下(截图中信号名被列宽截断, 以下按波形形状与数值判定)。

| 截图行 | 判定信号 | 比对依据 |
|--------|----------|----------|
| 第 1 行 | clk | 等周期方波, 与 25MHz 激励一致 |
| 第 2 行 | rst | 起始高电平一段后释放并保持低, 复位时序一致 |
| 第 3 行 | sample_valid | 周期性成组脉冲, 每组两拍——对应"每样本连发两拍"的样本重复法 |
| 第 4 行 | sample_left | 数值序列 1581568 / 2789632 / 3339008 / 3099904 / 2128384 / 654592 / -973824 / -2372352 / -3210752 / -3790624 / -2593536 / -1283840 / 328704, 与本 tb 的 sine_q[i]<<8 逐值一致(1581568 = 6178<<8, 2789632 = 10897<<8, -973824 = -3804<<8 ...), 即 1875Hz 正弦一个周期 |
| 第 5 行 | levels | 192 位总线全 0——截图仅覆盖 0~2us, 此时尚处采样阶段, 频谱电平未输出, 属预期 |
| 第 6 行 | fstate | 恒 0(采样阶段 IDLE), 与时间轴范围吻合 |
| 第 7 行 | samp_tgl | 0/1 交替(每样本两拍奇偶过滤) |
| 第 8 行 | waddr | 0→14 阶梯递增, 约 120ns(3 拍)一步, 与采样写入节奏一致 |

结论:
1. 该截图与本仿真环境完全一致, 正确复现了 testbench 的激励序列;
2. 截图只覆盖了前 2us, 属于采样阶段; 要看到频谱结果, 需把仿真跑到 20us 以后(直接 run -all), 届时 fstate 依次经过 1(蝶形)与 2(输出), levels 总线会刷新出 32 个频点电平;
3. 跑完整后若在 levels 上观察到上文"已知发现"所述的能量弥散现象, 即为已记录的 RTL 问题, 与本结论一致。

**终值解码(重要)**: 192 位 = 32 频点 x 6bit, 高位在前, 可见的高 21 个频点电平依次为
bin32..bin12 = 8, 17, 4, 49, 56, 53, 1, 9, 53, 29, 52, 23, 37, 35, 35, 20, 36, 20, 4, 22, 52。
(bin1..bin11 在截图省略号中被截断, 不可见。)

结论:
1. 单音 1875Hz 输入, 理论频谱应只在 bin5 出现单峰、其余频点为 0; 实测可见的 21 个频点全部非零(1~56), 峰值出现在 bin28(56)/bin29(49) 一带——**能量弥散全频段, 与本文档"已知发现"记录的 RTL 偏差完全一致**;
2. 至此三方证据闭环: 本机 ModelSim 批处理、第一张截图(采样阶段)、第二张截图(FFT 输出阶段) 相互印证——仿真环境正确, 偏差确系 RTL 变换本身;
3. 若答辩需要, 可将"两次独立仿真运行复现同一异常"作为仿真验证严谨性的佐证材料。
